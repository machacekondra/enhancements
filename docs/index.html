4

5

6

7
Agent in prod-eu-west-1 receives the request (prod-us-east-1 is not selected by the sovereignty policy).
8
Agent routes to the KubeVirt SP, which provisions the VM. Status flows back asynchronously.
1
Admin submits a CatalogItem blueprint defining resources, fields with defaults, validation schemas, and dependencies.
2
Catalog Manager validates service types exist, field paths are valid, JSON Schema constraints are correct, and dependency graph is acyclic.
3
CatalogItem appears in the Self-Service Portal for users to instantiate with their own parameter overrides.
1
Agent starts in the target environment, loads configuration, and creates three NATS topics (main, retry, cancel).
2
Embedded SPs register in-process (KubeVirt, K8s Container, ACM Cluster) based on agent config. Each claims a service type slot.
3
Agent creates three NATS topics for messaging: main (requests), retry (unhealthy holds), cancel (re-routing signals).
4
Agent self-registers with the control plane via POST /api/v1/agents, advertising its environment, service types, cost tier, and topic name.
5
Agent begins sending periodic heartbeats with timestamp and consumer_lag. DCM uses these for health and congestion monitoring.
1
An external SP registers with the agent via POST /api/v1/providers, declaring its service type, endpoint, and metadata.
2
Agent stores the SP registration, adds the new service type to its capability list, and starts health-checking the SP.
3
Agent updates DCM with its new service_types list via POST /api/v1/agents (idempotent by name).
4
On SP health changes, agent updates DCM: Unhealthy keeps the type listed; Unavailable removes it; Recovery re-adds it.

Policy Engine

Policies validate, mutate, and control agent selection for every resource request using embedded OPA/Rego.

Policy Outputs

FieldTypeDescription
rejectedbooleanIf true, request is denied immediately (406 response)
rejection_reasonstringHuman-readable reason for rejection
selected_agentstringName of the chosen agent
agent_constraintsobjectAllow-lists and patterns restricting agent selection for subsequent policies
patchobjectMutations to apply to the request spec
constraintsobjectJSON Schema constraints that lock fields for subsequent policies

Policy Management API

MethodEndpointDescription
POST/api/v1/policiesCreate policy (compiles Rego at creation time)

PUT/api/v1/policies/{id}Update policy (name/type immutable)
DELETE/api/v1/policies/{id}Delete policy

Placement Manager

Orchestrates resource provisioning: stores intent, builds DAGs, coordinates policy evaluation, manages retries and re-routing.

Service Deletion Flow

Deletion cannot be re-routed to a different agent. The resource exists on the original agent's SP.

Rehydration Flow →

Re-evaluate policies and agents for existing resources. Uses create-before-delete pattern with deferred cleanup. Click to explore.

Environment Agents & Service Providers

Each environment runs an agent that routes requests to local service providers and reports health to the control plane.

Agent Registration Data

FieldDescription
nameUnique natural key (e.g., "prod-eu-agent"). Used for idempotent re-registration.
environmentFreeform identifier (e.g., "prod-eu-west-1"). Used by policies for filtering.
service_typesList of supported types (e.g., ["vm", "container"]). Aggregated from registered SPs.
costTier: low, medium-low, medium, medium-high, high. Used by cost-based policies.
topic_nameDeterministic NATS topic (e.g., "dcm.agents.prod-eu-agent").
consumer_lagPending messages on topic. Reported in heartbeats.

NATS Topics per Agent

TopicDirectionPurpose
{topic_name}DCM → AgentCreation and deletion requests
{topic_name}.retryAgent-internalRequests held while SP is unhealthy
{topic_name}.cancelDCM → AgentCancellation signals for re-routed requests
dcm.agents.responsesAgent → DCMStatus acknowledgments, errors, queued notices
dcm.agents.healthAgent → DCMSP health degradation warnings

CloudEvent Types

Event TypeDirectionDescription
dcm.request.createDCM → AgentCreate a new resource instance
dcm.request.deleteDCM → AgentDelete an existing resource instance
dcm.request.cancelDCM → AgentCancel a previously sent request (re-routed or rehydrated)
dcm.agent.creation-acknowledgedAgent → DCMAgent confirmed creation request received
dcm.agent.deletion-acknowledgedAgent → DCMAgent confirmed deletion request received
dcm.agent.request-queuedAgent → DCMRequest held in retry topic (SP unhealthy)
dcm.agent.cancel-rejectedAgent → DCMCancel arrived too late; resource already provisioning
dcm.agent.errorAgent → DCMSP returned an error
